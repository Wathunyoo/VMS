4. ข้อบกพร่องที่พบระหว่างทดสอบและแก้ไขแล้ว

#อาการสาเหตุ / การแก้ไข
4.1ลูกค้าใหม่ login แล้วหน้าหลักโหลดไม่ขึ้นหน้าตั้งรหัสใหม่กับหน้าตั้งค่าเริ่มต้นส่งต่อกันวนไปมา → กำหนดลำดับ ตั้งรหัส → ตั้งค่าเริ่มต้น → ใช้งาน และเพิ่มชุดทดสอบไล่ลำดับหน้า
4.2ป้าย “จจ 9595” อ่านเป็น “จจ 1595”การอ่านครึ่งขวาตัดตัวเลขหลักแรก → ให้ผลแต่ละรอบโหวตกัน
4.3หน้า “ตั้งค่า” เปิดไม่ได้เมื่อใช้ระบบออนไลน์ข้อมูลเมนูอยู่ในไฟล์ฝั่งเบราว์เซอร์ → แยกไฟล์ และตรวจทุกหน้าในโหมดใช้งานจริง
4.4ค้นทะเบียน “1กข” ได้ผลเกิน (ไปตรงกับเบอร์โทร)ค้นเบอร์โทรเฉพาะเมื่อพิมพ์ตัวเลข ≥ 4 หลัก
4.5ฟอร์ม Check-in แจ้งข้อผิดพลาดไม่ครบในรอบเดียวรวมการตรวจตามการตั้งค่าแบบฟอร์มเข้ากับการตรวจพื้นฐาน
4.6แถบเมนูล้นจอบนโทรศัพท์ย่อเมนูเหลือไอคอนบนจอแคบ
4.7สถานะ E-Stamp ของหมู่บ้านแสดงคำว่า “Host”ใช้คำว่า “ลูกบ้าน” ตามโหมด
4.8การลบข้อมูล PDPA กรองเงื่อนไขทับกัน (พบก่อนใช้งาน)แก้การรวมเงื่อนไข และเพิ่มชุดทดสอบ

5. สิ่งที่ยังไม่ได้ทดสอบ (ต้องทดสอบที่หน้างาน)

เรื่องเหตุผลวิธีทดสอบที่แนะนำ
กล้องแท็บเล็ต: สแกนบัตร / ถ่ายหน้าทดสอบได้เฉพาะภาพจำลอง แสงและมุมกล้องจริงมีผลมากลองกับบัตรจริง 10–20 ใบ ทั้งในอาคารและกลางแจ้ง
อ่านป้ายทะเบียนจริงป้ายจำลองอ่านถูกทั้งหมด ~70% ตัวอักษรหมวดคลาดเคลื่อนได้ถ่ายรถจริง ≥ 20 คัน กลางวัน/กลางคืน บันทึกอัตราอ่านถูก
เครื่องพิมพ์สลิป 58/80 มม.ยังไม่มีเครื่องพิมพ์จริงพิมพ์บัตรผ่านและตรวจว่า QR สแกนได้ที่ Check-out
LINE แจ้งลูกบ้าน / E-Stamp บนมือถือต้องใช้มือถือจริงและระบบออนไลน์เชื่อม LINE 1–2 คน แล้วทดสอบอนุมัติจากมือถือ
ใช้งานต่อเนื่องหลายวันยังไม่เคยเปิดใช้ต่อเนื่องทดลองนำร่อง 2–4 สัปดาห์ ตรวจการสำรองข้อมูลรายวัน
อีเมล / ตรวจสลิปกับธนาคารยังไม่ได้ตั้งค่าบริการภายนอกทดสอบหลังตั้งค่า SMTP และ EasySlip

6. เงื่อนไขการใช้งานโปรแกรม (ฉบับปัจจุบัน)

เอกสารส่วนนี้เป็นเงื่อนไขทางเทคนิคและการใช้งานของโปรแกรมรุ่นนี้ — ไม่ใช่ “ข้อกำหนดการใช้บริการ” หรือ “นโยบายความเป็นส่วนตัว” ทางกฎหมายสำหรับลูกค้า ซึ่งต้องให้ทนาย/ผู้เชี่ยวชาญ PDPA จัดทำก่อนเปิดให้บริการ

6.1 ความต้องการของระบบ

6.2 เงื่อนไขการใช้งาน

  1. 1 องค์กร = 1 ประเภทธุรกิจ (หมู่บ้าน / อาคารสำนักงาน / โรงงาน) กำหนดโดยผู้ให้บริการตอนสร้างลูกค้า และเปลี่ยนภายหลังไม่ได้
  2. ลูกค้าใหม่สร้างโดยผู้ให้บริการเท่านั้น (ติดตั้งที่หน้างาน) — ไม่มีการสมัครใช้งานเอง · รหัสชั่วคราวต้องส่งให้ลูกค้าแบบส่วนตัว และลูกค้าต้องตั้งรหัสใหม่เมื่อ login ครั้งแรก
  3. จุด Check-in ผูกกับเบราว์เซอร์ — เบราว์เซอร์หนึ่งลงทะเบียนได้ทีละองค์กร จำนวนจุดจำกัดตามแพ็กเกจ (ทดลองใช้ 2 จุด) · Check-out ทำได้เสมอแม้หมดอายุบริการ
  4. ผลจากการอ่านอัตโนมัติ (บัตร/ป้ายทะเบียน/สลิป) เป็นตัวช่วยกรอก — เจ้าหน้าที่ต้องตรวจทานก่อนบันทึกทุกครั้ง ผู้ให้บริการไม่รับรองความถูกต้อง 100%
  5. ระบบออนไลน์แบบชั่วคราว ลิงก์จะเปลี่ยนทุกครั้งที่เปิดใหม่ (ต้องแก้ LINE Webhook ตาม) จนกว่าจะมีโดเมนถาวร/ย้ายขึ้น Cloud
  6. เวลาอยู่ได้ ตั้งต่อสถานที่ (0.5–168 ชม. หรือไม่จำกัด) และเลือกต่อรายได้ตอน Check-in · ผู้ที่ “ไม่จำกัดเวลา” จะไม่ถูกนับว่าอยู่เกินเวลา
  7. ค่าบริการ คิดตามจำนวนจุด Check-in · ราคาในระบบปัจจุบันเป็นราคาตัวอย่าง · ชำระโดยโอนเงินและแนบสลิป ผู้ให้บริการตรวจและออกใบเสร็จ

6.3 ข้อมูลส่วนบุคคล (PDPA) และความปลอดภัย

  • เก็บเลขบัตรเป็น แบบปิดบางส่วน และรหัสที่แปลงด้วยกุญแจลับ (ย้อนกลับไม่ได้) — ไม่เก็บเลขบัตรเต็ม · ไม่เก็บศาสนา/ที่อยู่/วันเกิดจากบัตร
  • ภาพใบหน้า ภาพบัตร และภาพป้ายทะเบียน เปิดดูได้เฉพาะเจ้าหน้าที่ขององค์กร และลบอัตโนมัติตามระยะเวลาที่ตั้ง (ค่าเริ่มต้น: รูป 90 วัน, ข้อมูลส่วนบุคคล 365 วัน) พร้อมบันทึกประวัติการลบ
  • การอ่านบัตรและป้ายทะเบียนประมวลผลในเครื่องของผู้ใช้ ไม่ส่งภาพไปบริการภายนอก · การแจ้ง LINE ไม่ส่งรูปใบหน้า
  • ผู้ติดต่อต้องให้ความยินยอม (PDPA) ทุกครั้งที่ Check-in · องค์กรลูกค้าในฐานะ “ผู้ควบคุมข้อมูล” ต้องมีประกาศความเป็นส่วนตัวที่จุด รปภ.
  • ข้อมูลแต่ละองค์กรแยกจากกัน (ทดสอบแล้ว 26 ข้อ) · รหัสผ่านเก็บแบบ scrypt · ผิด 5 ครั้งล็อก 15 นาที · Export Excel เฉพาะผู้ดูแลระบบ
  • สำรองข้อมูลอัตโนมัติวันละครั้ง (เก็บ 14 ชุด) ในเครื่องที่รันระบบ — ไฟล์สำรองมีข้อมูลส่วนบุคคลและรหัสลับ ต้องเก็บรักษาอย่างปลอดภัย

6.4 ข้อจำกัดของรุ่นปัจจุบัน

ข้อจำกัดผลกระทบแนวทาง
รันบน Mac เครื่องเดียวปิดเครื่อง/ไฟดับ = ระบบหยุดย้ายขึ้น Cloud (ระงับไว้ชั่วคราว)
ไฟล์สำรองอยู่ในเครื่องเดียวกับข้อมูลจริงเครื่องเสีย/หาย ข้อมูลหายทั้งหมดตั้งสำเนาเข้ารหัสไปไดรฟ์ภายนอกหรือคลาวด์
ยังไม่ได้ตั้งอีเมลของระบบลูกค้าไม่ได้รับใบเสร็จทางอีเมลตั้งค่า SMTP
